# Windows 桌面计时工具设计

日期：2026-09-02
状态：已确认，待实现

## 1. 目标与范围

这是一个 Windows 单平台的轻量桌面计时工具，用于记录每个实际工作时间段，并通过甘特图查看今天和历史日期做过什么。

核心需求：

- 小型计时窗口只展示当前标题、已进行时长、开始/暂停。
- 点击暂停立即结束当前时间段；暂停期间在甘特图中显示为空闲。
- 下一次开始时可更换标题、项目或分类，创建新的时间段。
- 标题支持手动输入、历史建议和预设项目/分类。
- 应用关闭后仍驻留系统托盘；计时继续，双击托盘图标恢复窗口。
- 提供始终置顶开关。
- 历史记录在独立的大窗口中显示，默认今天，并可切换历史日期。
- 应用重启时，未完成记录自动按暂停处理，不继续计时。

## 2. 技术架构

采用 Tauri v2 + React + TypeScript + Vite + SQLite。

Tauri 负责 Windows 窗口、系统托盘、窗口置顶、应用生命周期和打包；React 负责计时器和甘特图界面；SQLite 负责本地持久化。计时状态和数据库写入由 Rust/Tauri 后端负责，React 只读取状态并发起 command，避免窗口隐藏、页面切换或刷新影响计时。

应用包含两个窗口：

- `TimerWindow`：默认小尺寸，只显示标题、时长、开始/暂停按钮和设置入口。
- `HistoryWindow`：独立的大窗口，负责日期切换、甘特图、记录详情、当天统计和筛选。

托盘菜单提供显示计时器、打开历史、切换置顶和退出应用等操作。关闭主窗口只隐藏到托盘，不停止计时；只有真正退出应用时才自动暂停活动记录。

## 3. 全新数据库设计

不迁移、不保留当前数据库内容。实现开始时删除现有 `data/time_record.db`，重新初始化空数据库；运行时数据库通过 `.gitignore` 排除，不进入 Git 历史。

计划建立以下表：

### `time_entries`

一条记录代表一个完整的实际工作时间段：

- `id`
- `title`
- `project`（可选）
- `category`（可选）
- `color`
- `started_at`
- `ended_at`
- `created_at`

每次开始新增一行，暂停时写入 `ended_at`。每行天然对应甘特图中的一个区段，不合并中间的空闲时间。

### `presets`

保存可复用的标题、项目、分类、颜色及排序信息。手动输入的内容可以保存为预设。

### `settings`

保存置顶开关、窗口位置、窗口尺寸、最近选择等本地配置。

### `runtime_state`

保存当前活动记录 ID 和最后心跳时间，用于异常退出恢复。正常暂停后不保留活动记录。

时间统一以 UTC 存储，界面按 Windows 本地时区显示。启动时发现 `ended_at IS NULL` 的记录，以最后心跳时间结束并视为暂停。

## 4. 界面与交互

主窗口默认显示“未计时”。标题输入框同时提供历史建议；项目和分类放入展开区域，不强制填写。预设可一键填入标题、项目、分类和颜色。

开始操作时后端校验标题非空并创建新的 `time_entries` 记录；按钮变为“暂停”，时长根据时间戳计算。暂停操作立即结束当前记录，按钮恢复为“开始”，并保留本段已完成时长。没有“完成”按钮，也不维护额外的任务状态。

历史窗口默认显示今天。甘特图按小时排列横向时间轴，每条记录显示颜色、标题、开始时间和结束时间；点击区段可查看详情。下方显示当天总计、工作区段数和空闲时长。跨午夜记录不拆分数据库行，日期页面按可见时间区间裁剪显示。

## 5. 错误处理与边界情况

Rust 后端是计时状态的唯一事实来源。空标题、数据库写入失败或已有活动记录时返回明确错误，界面保持原状态并显示简短提示。没有活动记录时点击暂停按幂等操作处理，不创建空记录。

需要覆盖：快速连续点击、系统休眠后恢复、跨午夜、数据库不存在、数据库损坏、无记录日期、特殊字符标题、异常退出和残留未结束记录。所有写操作使用 SQLite 事务；失败时不改变原状态。

## 6. 测试与验收

分四层测试：

1. Rust 单元测试：时长计算、启动恢复、跨午夜、重复操作和数据库事务。
2. React 组件测试：按钮状态、输入校验、错误提示和甘特图渲染。
3. Tauri 集成测试：窗口、托盘、置顶开关及前后端 command 通信。
4. Windows 打包验收：安装包启动、托盘常驻、关闭/恢复窗口、重启恢复和数据库初始化。

## 7. Git 原子化提交约定

从项目初始化开始使用 Git。每个提交只包含一个可独立验证的主题，例如：

- `chore: initialize tauri react project`
- `feat: add fresh sqlite schema`
- `feat: implement start and pause timer`
- `feat: add tray resident behavior`
- `feat: add always-on-top setting`
- `feat: add history gantt window`
- `test: cover timer recovery and duration calculation`
- `docs: update implementation notes`

每次提交前运行对应测试或构建检查；阶段完成后再执行完整测试和 Windows 构建。源码、迁移脚本、测试、文档和配置模板纳入 Git；个人运行数据库、构建产物、依赖目录和本地环境文件不纳入 Git。

## 8. 备选方案与取舍

曾比较以下实现方式：

- Python + PySide6 + SQLite：Windows 原生能力直接，开发快，但界面生态和前端复用较弱。
- Tauri + React + SQLite：保留 Web UI 开发效率，同时具备桌面窗口和托盘能力；最终选择此方案。
- C# + WPF + SQLite：Windows 原生体验强，但技术栈与跨平台扩展性较弱。
