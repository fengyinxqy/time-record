# GitHub Releases 更新检查设计

日期：2026-09-11  
状态：已确认，待审阅

## 目标与范围

为 Windows 桌面应用增加自动更新检查：应用启动时在后台检查一次，用户也可以在设置窗口手动检查。发现较高版本时，应用展示版本号和发布说明，并将用户带到 GitHub Releases 页面自行下载安装包。

发布渠道为 `fengyinxqy/time-record` 的 GitHub Releases。该功能只检查和提示更新；不在应用内下载、安装或重启，也不接入 Tauri Updater、更新签名或更新清单。

范围外：预发布版本、草稿 Release、自动下载、静默安装、更新渠道切换和更新偏好持久化。

## 发布与版本约定

- 应用版本继续由 `src-tauri/tauri.conf.json` 中的 `version` 定义；`package.json` 与 `Cargo.toml` 在发布时必须同步。
- 正式版本以 `vX.Y.Z` Git 标签触发，例如 `v0.2.0`。标签去除可选的 `v` 前缀后必须与应用版本相同。
- GitHub Actions 仅在推送 `v*` 标签时运行。在 Windows runner 上安装 Node/Rust 依赖、运行前端测试、Rust 测试和前端构建，再执行 Tauri 打包。
- 工作流将 Windows 安装包作为对应 GitHub Release 的资产发布。发布失败不得生成不完整的 Release。

## 更新查询与领域逻辑

新增 `src/updateModel.ts`，保持网络数据和版本规则独立于 React 组件。

- 使用 `GET https://api.github.com/repos/fengyinxqy/time-record/releases/latest` 查询最新正式 Release。
- 只使用 `tag_name`、`name`、`body`、`html_url` 和 `published_at` 字段；响应缺失必要字段或标签不是有效的三段数字版本时，视为不可用结果。
- 比较规则遵循三段数字版本：去除一个可选 `v` 前缀，将 `major.minor.patch` 逐段以数字比较。Release 仅在严格高于本地版本时代表可用更新；相等或更低版本均为最新。
- `releases/latest` 本身排除 draft 和 prerelease；客户端不请求或显示它们。

## 界面与数据流

设置窗口新增“软件更新”区域，显示当前应用版本和“检查更新”按钮。

1. 设置窗口加载后显示当前版本，按钮可用。
2. 用户点击按钮时，进入检查中状态并禁用按钮，避免并发请求。
3. 查询返回较高版本时，显示“发现新版本 vX.Y.Z”、发布说明和“前往下载”按钮。按钮通过现有 `tauri-plugin-opener` 在默认系统浏览器打开该 Release 的 `html_url`。
4. 查询成功但没有较高版本时，显示“已是最新版本”。
5. 手动查询失败时，显示简短的可读错误；旧的成功结果不会被失败结果错误覆盖。
6. 主计时窗口初始化后异步发起一次相同查询。它不阻塞计时或窗口显示，也不展示成功、无更新、格式错误或网络失败状态；仅在有更新时以非阻塞提示引导用户打开设置窗口查看详情。

## 异常处理与安全边界

- 所有 GitHub 网络请求使用公开 API，不发送令牌或用户数据。
- 自动检查的任何错误均静默忽略，确保离线、GitHub 限流或网络异常不影响应用启动与计时。
- 手动检查将 HTTP 非成功状态、网络异常和无效响应统一映射为可读错误，不泄漏底层堆栈。
- Release 文本作为纯文本渲染；不将 GitHub 发布说明以 HTML 注入页面。
- GitHub API 的 `html_url` 仅在通过响应解析后用于系统浏览器打开；应用不下载或执行远程资产。

## 测试与验收

前端 Vitest 单元测试覆盖：

- 标签解析和三段版本比较：可选 `v` 前缀、相等、较新、较旧和无效版本。
- GitHub Release 响应的字段提取及缺失字段处理。
- 设置窗口的检查中、新版本、已是最新和手动查询失败状态。
- 自动检查不显示网络失败，且发现更新时能够引导用户到设置窗口。
- “前往下载”使用 opener 打开 Release 页面。

发布工作流验收：

1. 推送 `vX.Y.Z` 标签会执行测试和 Windows 打包。
2. 成功运行后会创建或更新同名 GitHub Release，并附上安装包资产。
3. 非标签推送不发布 Release。

手动 Windows 验收：

1. 将已安装应用的版本低于最新正式 Release 后启动，确认计时窗口不被检查阻塞且可获知新版本。
2. 在设置窗口手动检查，确认可显示版本与发布说明，并通过浏览器转到正确的 Release 页面。
3. 断网后启动应用，确认不出现打扰性错误；手动检查时确认显示可读错误。
