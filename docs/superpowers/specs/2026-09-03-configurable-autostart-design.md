# 可配置开机自启动与静默启动设计

日期：2026-09-03
状态：已确认，待实现

## 目标与范围

为 Windows 版时间记录应用增加独立设置窗口，允许用户配置当前 Windows 用户的开机自启动，并决定开机自启动时是否仅驻留系统托盘。

- 主窗口顶部提供“设置”入口。
- 设置窗口提供“开机自启动”和“静默启动”两个开关。
- 两个偏好均默认关闭，并且独立持久化。
- 静默启动仅影响由开机启动项传入内部参数的进程；用户双击图标或从其他方式手动启动应用时，仍正常显示计时器窗口。
- 开机自启动关闭时，“静默启动”保留其设置值但不可编辑；重新开启开机自启动后，按已保存的静默偏好重新写入启动项。

本功能不修改计时、历史窗口、关闭到托盘或退出时暂停计时的既有行为。

## 架构与职责

### Rust/Tauri 后端

后端新增 Windows 启动项模块，唯一负责：

- 在 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 读取、创建和删除本应用的启动项。
- 将应用的当前可执行文件路径安全加引号，保证包含空格的安装路径可以正常启动。
- 根据持久化的静默偏好，在启动项命令后附加内部参数 `--silent-start`。
- 在开发模式或无法获取可靠可执行文件路径时，拒绝启用自启动并返回可展示的错误。
- 判断当前进程是否携带 `--silent-start`，据此决定是否隐藏计时器窗口。

后端提供 Tauri commands：

- 读取当前的自启动状态和静默启动偏好。
- 更新开机自启动状态：写入或移除启动项；若启用，则使用当前静默偏好生成启动命令。
- 更新静默启动偏好：持久化偏好；若自启动已启用，则立即重写启动项使其生效。
- 显示、隐藏和聚焦设置窗口。

应用初始化时始终创建系统托盘。若启动参数包含 `--silent-start`，不展示计时器窗口；否则按现有配置正常展示。设置窗口与历史窗口一致：用户关闭时阻止销毁并隐藏。

### 持久化

在现有 SQLite 数据库中保存静默启动偏好，以便关闭自启动后重新启用时仍能恢复用户选择。注册表是自启动是否实际启用的权威来源；后端读取时将注册表状态与保存的静默偏好组合返回。

## 窗口与交互

Tauri 配置新增初始隐藏的 `settings` 窗口。前端通过窗口标签识别该窗口，并渲染一个独立的 `SettingsWindow`。

主窗口顶部在“置顶”“历史”旁新增“设置”按钮。点击后显示、聚焦设置窗口。

设置窗口显示：

1. **开机自启动**：默认关闭。用户打开时，后端在当前用户的注册表启动项写入本应用可执行文件；关闭时移除该启动项。
2. **静默启动**：默认关闭。当开机自启动关闭时，此开关禁用但保留已选择的值。当开机自启动开启且该值为真时，写入的启动项附加 `--silent-start`。

所有开关在请求完成前使用当前状态。后端成功后才更新前端状态；失败时保留原状态并展示错误消息。静默设置更新成功后，若自启动开启，注册表项立即同步更新。

## 异常处理

- 读取或写入注册表失败时，Tauri command 返回明确错误，前端不改变开关状态。
- 无法确定可执行文件路径时，不创建启动项，避免写入无效的注册表数据。
- 应用只以存在 `--silent-start` 参数作为静默启动条件；该参数不改变任何其他启动路径的窗口行为。
- 删除不存在的启动项应视为成功，使关闭自启动操作保持幂等。

## 测试与验收

Rust 单元测试覆盖纯逻辑：

- `--silent-start` 参数识别。
- 注册表启动命令的可执行文件路径引号与参数组合。
- 根据两个偏好生成正确启动项命令。

前端测试覆盖：

- 窗口标签正确路由至设置窗口。
- 加载设置、切换自启动、切换静默启动的请求与成功状态。
- 自启动关闭时静默开关禁用，且保留已保存值。
- 后端失败时保持原开关状态并显示错误。

手动 Windows 验收：

1. 在设置窗口启用和关闭开机自启动，确认当前用户 `Run` 启动项随之创建或删除。
2. 启用自启动与静默启动后，通过该启动项运行，确认应用只在系统托盘驻留，主窗口不出现。
3. 在静默偏好开启的情况下手动启动应用，确认计时器窗口仍正常显示。
4. 从托盘点击图标或选择“显示计时器”，确认能恢复主窗口。
5. 关闭自启动、重新开启后，确认已保存的静默偏好继续生效。
