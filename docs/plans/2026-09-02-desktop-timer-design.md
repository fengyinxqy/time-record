# Windows 桌面计时工具设计

日期：2026-09-02
状态：已确认，待按列表模型实现

## 1. 目标与范围

这是一个 Windows 单平台的轻量桌面计时工具。小窗口用于快速切换项目和开始/暂停计时；独立的大后台页面用于查看今天和历史日期的甘特图。

核心规则：

- 小窗口只显示长期项目列表，不显示今日概览。
- 列表中的一行就是一个项目/工作项，名称同时作为甘特图的行名称。
- 每行右侧只有明确的“开始/暂停”按钮；点击项目行本身不触发计时。
- 新增项目只加入列表，不自动开始；用户随后点击该项目的“开始”。
- 同一时间只有一个项目计时。开始另一个项目时，当前项目自动暂停。
- 点击暂停立即结束当前时间段；之后的空闲时间在甘特图中留白。
- 项目长期保留；项目支持归档/隐藏，归档项目不出现在当前列表，但历史记录仍可查看。
- 独立后台页面默认显示今天，可切换查看历史日期和完整甘特图。

## 2. 技术架构

采用 Tauri v2 + React + TypeScript + Vite + SQLite。

Tauri 负责 Windows 窗口、系统托盘、窗口置顶、应用生命周期和打包；React 负责项目列表和甘特图界面；SQLite 负责本地持久化。计时状态和数据库写入由 Rust/Tauri 后端负责，React 只读取状态并发起 command，避免窗口隐藏、页面切换或刷新影响计时。

应用包含两个窗口：

- `TimerWindow`：默认小尺寸，只显示项目列表、项目累计时长、开始/暂停按钮、新增输入框和设置入口。
- `HistoryWindow`：独立的大窗口，负责日期切换、统计、按项目分行的甘特图和记录详情。

托盘菜单提供显示计时器、打开历史、切换置顶和退出应用等操作。关闭主窗口只隐藏到托盘，不停止计时；退出应用时自动暂停当前项目。

## 3. 全新数据库设计

不迁移、不保留之前的数据库内容。实现阶段删除现有 `data/time_record.db`，重新初始化空数据库；运行时数据库不进入 Git 历史。

### `projects`

保存长期项目/工作项：

- `id`
- `name`
- `color`
- `sort_order`
- `archived`
- `created_at`

项目名称唯一。新增后立即显示在列表中，但不自动开始计时。归档只影响当前列表，不删除历史数据。

### `time_segments`

保存实际计时区段：

- `id`
- `project_id`
- `started_at`
- `ended_at`
- `created_at`

每次点击项目的“开始”创建一个区段；点击暂停或切换项目时写入 `ended_at`。同一项目一天内可以有多个区段，甘特图在同一项目行中绘制多个色块。

### `settings`

保存置顶开关、窗口位置、窗口尺寸等本地设置。

### `runtime_state`

保存当前活动区段 ID 和最后心跳时间，用于异常退出恢复。应用重启发现未结束区段时，以最后心跳时间结束，并视为暂停。

时间统一以 UTC 存储，界面按 Windows 本地时区显示。

## 4. 界面与交互

主窗口默认显示项目列表。每行包含颜色标记、项目名称、已用时长和右侧操作按钮。当前运行项目高亮，按钮显示“暂停”；其他项目按钮显示“开始”。项目行本身不响应点击，只有右侧按钮可以改变计时状态。

底部提供“输入新的工作内容”和“新增”按钮。新增成功后项目进入列表但保持未计时状态。项目的归档操作放在行的次级菜单中，不占用主要计时按钮位置。

开始某个未运行项目时，如果另一个项目正在运行，后端在一个事务内先结束旧区段，再创建新区段。暂停当前项目只结束当前区段，不自动开始其他项目。

历史窗口默认显示今天。纵轴按项目分行，横轴为一天的时间轴。同一项目的多次计时在同一行显示多个独立色块，项目之间的空白表示空闲。可查看当天总计、区段数和空闲时长，也可切换历史日期。

## 5. 错误处理与边界情况

Rust 后端是计时状态的唯一事实来源。项目名称为空、名称重复、数据库写入失败或状态冲突时返回明确错误，界面保持原状态并显示提示。没有活动区段时点击暂停按幂等操作处理。

需要覆盖：快速连续点击、切换项目、系统休眠后恢复、跨午夜、归档项目仍有历史记录、数据库不存在、数据库损坏、无记录日期、特殊字符名称、异常退出和残留未结束区段。所有写操作使用 SQLite 事务；失败时不改变原状态。

## 6. 测试与验收

分四层测试：

1. Rust 单元测试：时长计算、项目切换、暂停、启动恢复、跨午夜和数据库事务。
2. React 组件测试：列表渲染、按钮状态、新增不自动开始、项目切换和错误提示。
3. Tauri 集成测试：窗口、托盘、置顶开关及前后端 command 通信。
4. Windows 打包验收：安装包启动、托盘常驻、关闭/恢复窗口、重启恢复和数据库初始化。

## 7. Git 原子化提交约定

每个提交只包含一个可独立验证的主题，例如：

- `feat: replace entries with persistent projects`
- `feat: switch timer from project buttons`
- `feat: add project-row gantt history`
- `feat: add tray resident behavior`
- `test: cover project switching and recovery`

每次提交前运行对应测试或构建检查；阶段完成后再执行完整测试和 Windows 构建。源码、测试、设计文档和配置模板纳入 Git；个人运行数据库、构建产物、依赖目录和本地环境文件不纳入 Git。

## 8. 方案取舍

实现方式采用 Tauri + React + SQLite，而不是 Python + PySide6 或 C# + WPF。小窗口和后台页面分离，避免为了查看统计牺牲计时器的紧凑性；项目与时间区段分表，保证一个项目在甘特图中固定一行，同时允许保留多个独立时间段。
