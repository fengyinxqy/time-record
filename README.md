# 时间记录 · Time Record

**记录每天做了什么，让时间的去向清晰可见。**

一款面向 Windows 的个人桌面时间记录工具。<br />
切换工作、一键计时、回看时间轴，把每天的投入留在自己的电脑里。

Tauri 2 · React 19 · TypeScript · Rust · SQLite

## 项目介绍

一天结束后，我们往往记得自己很忙，却很难说清时间具体花在了哪里。

时间记录围绕一个简单的需求展开：**记录每天做了什么。** 将写代码、阅读、学习、会议等活动建立为项目，开始工作时点击计时，切换任务时直接启动下一个项目，再通过每日时间轴回顾自己的时间分配。

项目采用紧凑的桌面窗口与系统托盘交互，适合在日常工作中随手使用。核心记录保存在本地 SQLite 数据库，无需注册账号，也无需配置服务器。

它适合个人工作复盘、学习投入记录，以及多个任务之间的时间分配回顾。当前项目版本为 `0.1.0`，开发与原生功能以 Windows 为目标。

## 功能介绍

| 功能 | 说明 |
| --- | --- |
| 项目计时 | 新建工作内容，点击开始或暂停，查看项目当天累计时长 |
| 自动切换 | 启动另一个项目时结束上一段计时，同一时刻只记录一个项目 |
| 归档与恢复 | 将暂时不用的项目移出主列表，保留历史，通过输入框中的归档建议恢复 |
| 每日时间轴 | 按项目展示一天中各段记录的实际位置，查看工作总计、项目数与记录明细 |
| 历史回顾 | 切换前一天、后一天，或回到今天；跨日记录按当天范围展示 |
| JSON 导出 | 指定起止日期和时间，通过系统保存对话框导出记录 |
| 桌面常驻 | 支持窗口置顶、关闭后隐藏到托盘、点击托盘重新打开 |
| 启动设置 | 支持 Windows 开机自启动，可选择启动时仅驻留托盘 |
| 外观设置 | 支持亮色、深色和跟随系统主题 |
| 异常恢复 | 持久化运行心跳，重新启动时结束异常遗留的计时段 |

### 三个窗口，各司其职

| 窗口 | 用途 |
| --- | --- |
| 计时器 | 日常新增、切换、暂停和归档项目，查看今日投入 |
| 历史记录 | 回看每日时间轴、统计和明细，导出指定时段的数据 |
| 设置 | 调整外观、开机自启动和静默启动 |

## 使用指南

### 1. 建立工作内容

在计时器底部的「输入新的工作内容…」中输入名称，点击「新增」，例如「写代码」「阅读」「课程学习」。项目创建后，点击对应的「开始」进入计时。

### 2. 随工作切换计时

- **继续当前工作**：保持计时，项目行显示当天累计时长。
- **切换任务**：点击另一个项目的「开始」，上一段计时自动结束。
- **暂时休息**：点击当前项目的「暂停」，暂停后的时间不计入项目。
- **保持可见**：点击右上角「置顶」，让计时器保持在其他窗口上方。

例如：09:00 开始「写代码」，10:00 切换到「阅读」，10:30 点击暂停，会留下两段记录：写代码 1 小时、阅读 30 分钟。

### 3. 回看一天

点击「历史」进入独立的历史记录窗口，通过左右箭头切换日期，或点击「今天」返回当天。

时间轴按 `00:00–24:00` 展示每个项目的记录，明细中可查看各段的起止时间与时长。尚未结束的时段会标记为「计时中」。

「空闲时间」当前按 **24 小时减去当天已记录时长** 计算，包含当天尚未到来的时间；它不是键盘、鼠标活动检测结果。

### 4. 整理项目

点击项目的「归档」并确认，可将项目从日常列表中隐藏，历史记录仍然保留。之后在新增工作内容输入框中查找归档项目，点击建议项即可恢复。

正在计时的项目不能直接归档，请先暂停计时，再进行归档。

### 5. 托盘与启动

- 关闭计时器、历史或设置窗口，只会隐藏窗口，应用仍在运行。
- 左键点击系统托盘图标，可重新显示计时器。
- 右键打开托盘菜单，可显示计时器、打开历史记录或退出应用。
- 从托盘选择「退出」时，会结束当前计时并退出进程。
- 在「设置」中开启「开机自启动」，可随 Windows 用户登录启动应用；开启「静默启动」后，自启动时仅驻留托盘。

静默启动选项在开启自启动后可调整，普通手动启动仍会显示计时器。开发模式禁止启用自启动，请使用打包后的应用验证此功能。

## 运行与打包

以下命令在项目根目录执行。可先克隆仓库，或下载源码并解压，再进入 `time-record` 目录。

### 环境准备

| 依赖 | 要求或用途 |
| --- | --- |
| Windows | 当前原生实现的目标平台 |
| Node.js 与 npm | Vite 7 要求 Node.js `20.19+`（20.x）或 `22.12+`；npm 用于安装依赖和执行脚本 |
| Rust 与 Cargo | 编译 Rust 后端，Windows 使用 MSVC 工具链 |
| Microsoft C++ Build Tools | 安装「使用 C++ 的桌面开发」工作负载及 Windows SDK |
| Microsoft Edge WebView2 Runtime | 运行桌面 WebView 界面 |

系统依赖的安装步骤见 [Tauri 2 官方环境准备文档](https://v2.tauri.app/start/prerequisites/)。SQLite 通过 `rusqlite` 的 `bundled` 功能随构建集成，无需单独安装数据库服务。

### 启动完整桌面应用

```powershell
npm install
npm run tauri -- dev
```

Tauri 会自动启动 Vite 开发服务器并打开桌面应用，首次启动需要编译 Rust 依赖。

### 仅启动前端开发服务器

```powershell
npm run dev
```

开发地址为 `http://localhost:1420`。该命令用于前端开发服务；当前应用依赖 Tauri 窗口 API 与 Rust 命令，直接在普通浏览器打开不能完整使用计时、数据库、托盘和文件导出功能。日常调试优先使用完整桌面启动命令。

### 构建桌面安装包

```powershell
npm run tauri -- build
```

该命令会先执行前端构建，再编译原生应用并生成安装包。默认输出位置：

```text
src-tauri/target/release/         # 原生可执行文件
src-tauri/target/release/bundle/  # 安装包
```

具体产物以构建日志为准；若配置了 `CARGO_TARGET_DIR`，输出位置会随之变化。安装构建得到的安装包后，即可通过应用入口运行，无需启动开发服务器。

仅检查 TypeScript 并构建前端资源：

```powershell
npm run build
```

前端产物写入 `dist/`，这一步不生成桌面安装包。

## 数据与导出

### 本地存储

项目、时间段、静默启动偏好和计时恢复状态保存在 Tauri 应用数据目录中的 `time_record.db`。当前应用标识为 `com.hermes.timerecord`，Windows 默认路径通常为：

```text
%APPDATA%\com.hermes.timerecord\time_record.db
```

实际位置由 Tauri 的 `app_data_dir()` 决定。主题偏好保存在 WebView 的 `localStorage` 中，Windows 自启动配置保存在当前用户的启动项注册表中。

核心记录流程不依赖远程服务，目前没有账号系统或云端同步。如需保留完整记录，可先从托盘退出应用，再复制数据库文件作为备份；该文件不包含主题偏好和 Windows 自启动配置。

### 导出 JSON

在历史窗口底部选择起始时间和结束时间，点击「导出 JSON」，再选择保存位置。默认文件名形如：

```text
time-record-2026-09-02T09-30_to_2026-09-02T10-15.json
```

导出的顶层字段为 `projects` 和 `timeSegments`，以下为格式示例：

```json
{
  "projects": [
    {
      "id": 1,
      "name": "写代码",
      "color": "#a69bd6",
      "sortOrder": 0,
      "archived": false,
      "createdAt": 1700000000,
      "updatedAt": 1700000000
    }
  ],
  "timeSegments": [
    {
      "id": 1,
      "projectId": 1,
      "startedAt": 1700000000,
      "endedAt": 1700003600,
      "createdAt": 1700000000,
      "updatedAt": 1700003600
    }
  ]
}
```

导出规则：

- 时间字段使用 Unix 时间戳，单位为秒；进行中的记录 `endedAt` 为 `null`。
- 选择范围采用左闭右开区间，即包含开始时刻、不包含结束时刻。
- 导出与范围重叠的时间段，并保留原始起止时间，不裁剪为选定范围。
- 同时包含这些记录关联的项目，以及在范围内创建或更新的项目。

JSON 适合自行分析或交给其他工具处理。当前没有 JSON 导入界面，范围导出也不等同于完整数据库备份。

### 异常退出后的记录

计时期间，前端定期向后端写入心跳。应用下次启动时，会检查未结束的计时段，通常以最后一次已保存心跳作为结束时间，然后回到暂停状态。这可以避免将应用退出后的整段时间误计为工作时间；恢复精度取决于最后一次成功写入的心跳。

## 技术实现

| 层次 | 技术 | 职责 |
| --- | --- | --- |
| 界面 | React 19、TypeScript、CSS、Radix UI | 计时器、历史、设置和交互组件 |
| 前端构建 | Vite 7 | 开发服务器与静态资源构建 |
| 桌面容器 | Tauri 2 | 多窗口、托盘、置顶、系统保存对话框 |
| 原生逻辑 | Rust | 命令处理、时间范围换算、启动与退出处理 |
| 数据持久化 | SQLite、rusqlite | 项目、时间段、运行状态与设置 |
| Windows 集成 | winreg、Windows API | 用户自启动注册表与窗口标题栏外观 |
| 测试 | Vitest、Rust 单元测试 | 前端领域逻辑、数据库行为和原生辅助逻辑 |

React 通过 Tauri 的 `invoke` 调用 Rust 命令，由后端统一读写数据库。开始、切换与暂停以时间段为单位保存，界面根据起止时间计算时长；历史视图再按当天边界裁剪和分组展示。

可从这个项目了解的实现内容包括：桌面多窗口交互、前后端类型约定、互斥计时状态、事务化存储、异常恢复、日期边界处理，以及 Windows 原生能力集成。

## 常见问题

### 关闭窗口后为什么还在计时？

关闭按钮用于隐藏窗口，方便应用常驻。需要停止计时请点击项目的「暂停」；需要完全退出请使用托盘菜单中的「退出」。

### 可以同时给多个项目计时吗？

目前同一时刻只支持一个计时项目。启动另一个项目会自动结束当前计时段。

### 归档会删除历史记录吗？

不会。归档只改变项目在日常列表中的可见性，历史时间段和关联关系仍然保留。

### 为什么开发模式不能开启自启动？

开发模式的可执行文件依赖开发环境，不适合作为用户登录后的启动入口。请先打包并安装应用，再设置自启动。

### 支持 macOS、Linux 或手机吗？

当前以 Windows 为目标。自启动模块使用 Windows 注册表实现，尚未提供其他平台的对应实现；仓库中的其他平台图标不代表已经支持这些平台。

### 支持补录、修改时间段或自动识别工作内容吗？

当前界面围绕手动开始、切换和暂停展开，尚未提供历史时间段编辑、补录、自动活动识别、云同步或团队协作功能。

### 不同时区都能准确统计吗？

界面使用本地日期与时间，当前后端查询与导出接收整数小时的时区偏移。非整小时时区，以及涉及夏令时变化的历史日期，仍需进一步适配与验证。
